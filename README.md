# AF-SDR

C# / .NET 9 / WinForms / Windows x64 の最小構成RTL-SDRスペクトラム表示アプリです。

## AF-SignalGenerator（独立EXE）

同じAF-SDR.slnに、既知のデジタル変調IQ WAVを生成するAF-SignalGenerator 1.0.0を追加しました。Releaseビルド後、`AF-SignalGenerator/bin/Release/net9.0-windows/AF-SignalGenerator.exe` で単独起動できます。AF-SDR本体のバージョンは1.12.1です。

[生成器の使い方・数式・JSON仕様・検証結果](AF-SignalGenerator/SIGNAL-MODEL.md)。GoldenはQPSK / 100 MHz / 9600 baud / α=.35 / 250 kS/s / −20 dBFS / 10秒。Generateで作ったWAVをAF-SDRのIQファイル入力で開き、デジタル表示をQPSK・9600 baud・α=.35に設定すると確認できます。FM音声はOFFにしてください。

## ビルド・起動

インストール済みの .NET 9 SDK を使用します。外部NuGetパッケージは不要です。

```powershell
cd W:\dev\AF-SDR
dotnet build AF-SDR.sln -c Release
.\AF-SDR\bin\Release-1.12.1\AF-SDR.exe
```

1. デバイスを選択します。必要なら「再検索」を押します。
2. 中心周波数を **HzまたはSI接頭語付き** で入力し、「接続」を押します（初期値80M）。例: `78.4M` → 78,400,000 Hz、`8400k` → 8,400,000 Hz、`100M` → 100,000,000 Hz、`500k` → 500,000 Hz。
3. 受信中は数値を変更して「周波数を適用」またはEnterで変更します。
4. スペクトラムまたはウォーターフォール上にマウスを置くと、カーソル周波数をHz/MHzで表示します。左クリックするとその位置を中心周波数に設定します。
5. 下段のウォーターフォールで信号の時間変化を確認できます。最新が上、過去が下です。
6. 「切断」で停止します。ウィンドウを閉じる際も受信終了後にデバイスを解放します。

`k/K`は千倍、`M/m`は百万倍、`G/g`は十億倍です（周波数入力の便宜上、mもMHzとして扱います）。接頭語なしはHzです。`78.4 MHz`、`500 KHZ`、`78,400,000`も入力できます。小数点はピリオド、カンマは3桁区切りとして扱います。設定成功後も `78.4M`、`8.4M`、`500k` のようにSI接頭語で表示します。整数Hzの精度は維持します。

入力範囲は1～4,294,967,295 Hzで、Hzに換算して整数になる値を受け付けます。不正入力は入力欄のエラーアイコンに表示し、受信・履歴を維持します。実際に受信できる範囲はドングルに依存し、設定エラーは画面下部に表示します。周波数変更時はUSBストリームを一旦停止しますが、デバイス接続は維持します。古い周波数のデータとFFT平均値・表示履歴は破棄します。

## I/Q（同期なし）の実サンプル軌跡（1.12.1）

I/Qモードだけ、軌跡を中間IQサンプルの経路へ改善しました。手動周波数補正 → 既存の間引き・選択RRC α・振幅正規化 → 表示用リサンプリング → 代表点／全サンプル軌跡の順です。内部固定8 samples/symbolなので、250 kS/s・9600 baudでも表示用IQは76,800 S/sになります。64タップBlackman窓sinc FIR（1024分割の分数遅延テーブル）で帯域制限とリサンプリングを行い、単にシンボル点を直線補間して軌跡を作る処理ではありません。

初期64シンボル相当を捨て、次の256シンボルの位相別平均電力が最大になる位置を代表位相として選びます。近傍3点の放物線で分数位相を一度だけ補正し、以後は指定Symbol Rateの等間隔クロックと代表位相を固定します。QPSK等の判定・搬送波同期・継続的なbaud追従は行いません。9600 baudで初期表示まで約34 ms＋表示更新待ちが必要です。無信号やタイミングの手掛かりが弱い信号で、代表点が判定位相になる保証はありません。

表示数Nでは同じ時間範囲の代表点を最大N個、軌跡を最大N×8サンプル描画します。例: 512点なら4096サンプルの軌跡です。完全な8サンプル区間だけを保持するため、点と軌跡の時間範囲は一致します。軌跡OFFは点のみとなり、ON/OFF・表示数変更でDSPはリセットしません。ブロックや画面更新ごとにリサンプル位相を初期化しません。既存の方式／Symbol Rate／RRC変更、シーク、欠落等によるDSP再構成時には初期位相を取り直します。Fine Tune変更だけでは位相選択や履歴をリセットしません。

既知QPSKで代表点EVM約1.31%、αを送受信で揃えた比較でα=.2は約2.04%、α=1は約1.24%を確認しました。同じ録音の受信側αだけを変えても中間IQが変化します。α=1では実波形そのものが直線に近い遷移となる場合がありますが、α=.2では曲がった遷移が見えます。設定baudを9700へずらすと点群が崩れ、手動補正なしの＋100 Hzも回転したままで、ずれを自動的に隠しません。最大8192サンプル描画は検証環境で約11 ms/フレームでした。

QPSK/QAM/π/4差動/ASK/FSK/MSK等の専用モードのDSP・補助線表示、操作UI、状態保存は変更していません。SPS/位相設定UIや新しい専用モードもありません。記事前の調整はこの範囲で完了とします。

## コンスタレーションの操作・表示・状態保存（1.12.0）

上部は変調形式、RRC α、多値数、FSKトーン間隔などの解析条件です。変更後は「適用」を押します。その下の **Symbol Rate → 手動周波数補正** は桁選択式の即時調整です。Symbol Rateは初期9600 baud、符号のない絶対値（8桁、整数baud）で、任意桁クリック＋Wheel/▲▼、矢印キー、直接入力・Enter/フォーカス移動による確定に対応します。「適用」は不要です。方式を変更して適用してもSymbol Rateと手動周波数補正は保持します。未適用の方式変更は、即時調整や表示ON/OFFでは適用されません。

Symbol Rateは1000～100000 baudかつ入力サンプルレートの1/8以下。FSK間隔等との組み合わせが帯域制約を超える調整は、理由を表示して元の値に戻します。サンプルレートを下げた場合は、従来どおり使用可能な範囲へ正規化します。Symbol Rate変更では既存のデジタルフィルター／同期処理を新しいbaudで再構成します。短い再取得時間があり、QAMは2048シンボルの取得を要します。親の周波数、受信接続、FM、FFT／ウォーターフォール、WAVの再生位置は維持します。自動baud検出や新しい通信解析処理は追加していません。

「表示シンボル数」は最新64／128／256／512／1024点から選択し、初期値256です。「軌跡」は初期OFF。専用モードのONでは同じ最新N点を古い順に低輝度・1ピクセル幅の線で結び、その上に点を描きます。I/Qモードは1.12.1から上記の中間IQサンプル軌跡です。判定や波形の補間結果ではなく、シンボル遷移を見る補助表示です。点数・軌跡は描画だけへ即時反映し、再生・DSP・同期・保持中の最大1024点はリセットしません。ASK/FSK/MSKの下段時間波形は従来の約16シンボル表示を維持します。I/Q（同期なし）の点は指定baudと初期代表位相に基づく観測点で、方式固有の判定点ではありません。

既存の `%LOCALAPPDATA%/AF-SDR/settings.json` へ、親アプリ正常終了時にコンスタレーションの位置・通常サイズ・最大化状態、適用済み変調設定（各方式の多値数・FSK間隔を含む）、Symbol Rate、手動周波数補正、表示点数、軌跡を保存します。画面を一度も開かなかった場合も前回配置を保持します。次回初回表示時には親と同じ画面領域補正を行い、負座標の第2モニター配置を保持しつつ、切断されたモニターや小さい画面には安全に収め直します。最小化、表示ON、接続・再生の自動開始は復元しません。リセット機能はありません。

未変更のAF-SignalGeneratorで生成した真値9600 baudのQPSK WAVを使い、再生中に9700→9690→…→9600へWheelで操作し、最終EVM約1.3%の4点表示を確認しました。全点数・軌跡切替、設定保存・再読込、モニター切断・最大化復元、既存回帰も自動検証しています。

## デジタル表示のFine Tune（1.11.0）

コンスタレーション画面の「手動周波数補正」は±10,000.0 Hz、0.1 Hz単位です。任意の数字を左クリックすると青く選択され、ホイールまたは▲/▼でその桁単位に増減します。矢印の左右で桁移動、上下で増減もできます。「直接入力」（またはダブルクリック/F2）では符号付きHzを入力し、Enterまたはフォーカス移動で確定します。Escで入力を取り消します。変更は即時反映され、上段の「適用」は不要です。不正値は拒否し、赤い入力欄と説明を表示します。

**信号の＋100 Hz偏差を除去する値は＋100.0 Hzです。** デジタルIQへ `z[n] × exp(-jφ[n])`、`φ[n+1] = φ[n] + 2π × 手動補正 / Fs` を適用します。位相はサンプルごとに積算し、ブロック境界・表示更新・補正値変更でも連続します。処理順は、既存の親側入力／選局 → 手動NCO → デジタル間引き／チャネル・整合フィルター → 既存のタイミング／搬送波処理 → 表示です。共有IQ配列を書き換えないため、FM・スペクトラムには補正が入りません。デジタル画面独自のFcはなく、基準は親側の0IFのままです。

BPSK/QPSK/QAM/π/4 QPSKの「推定残差（手動補正後）」は既存DSPの推定値であり、手動設定値とは別です。既存の自動搬送波同期を維持するため、＋100 HzのQPSKでも手動補正0の状態から4点に収束する場合があります。回転だけでなく推定残差が0 Hzに近づくことを見て追い込んでください。I/Q・ASK・FSK・MSKには元々の搬送波残差推定がなく、架空の推定値は表示しません。

手動補正のみの変更ではNCO位相、フィルター、タイミング・搬送波同期、表示点履歴、FFT・ウォーターフォール、FM・音声キュー、再生位置を維持します。ライブでは次のデジタル処理ブロック、ファイルでは次の処理ブロックから反映し、表示は既存の約40 ms周期です。記録帯域からはみ出る補正は拒否します。サンプル欠落、切断、シーク、ループ、方式・baud等の変更では従来どおり必要なDSPを再初期化します。補正値は終了時に保存・復元しますが、表示ONや受信・再生の自動開始は復元しません。

新版EXEと同じフォルダーの `FineTuneSamples/Golden` と `FineTuneSamples/OffsetPlus100Hz` に、未変更のAF-SignalGenerator 1.0.0で生成した10秒のQPSK WAVとJSONを同梱しています。親側100 MHz、QPSK／9600 baud／RRC .35、FM OFFで再生し、必要ならループを有効にしてください。＋100 Hzファイルでは、補正99／100／101 Hzの順で残差が約＋1／0／−1 Hzになります。試験用ファイルは次のコマンドで再生成できます。

```powershell
dotnet run --project AF-SDR.Checks -c Release --no-build -- --fine-tune-samples .\AF-SDR\bin\Release-1.12.1\FineTuneSamples
```

Release成果物は今後 `AF-SDR/bin/Release-<Version>/` に直接出力します。従来の `Release/net9.0-windows` は更新しません。

## IQ WAVファイルの再生（1.10.0）

1. 左上の入力源を「IQ WAVファイル」に切り替え、「IQ WAVを開く…」で録音を選択します。保存されたパスは「読み込み」で開き直せます。
2. 形式・サンプルレート・時間を確認します。記録中心はファイル名の `283487500Hz` 等から取得します。不明な場合は記録中心欄へ入力してください。
3. 「再生」で1倍再生、「一時停止」で連続状態を維持して停止します。「停止（先頭）」は先頭へ戻します。スライダーでシークでき、「ループ」で終端から繰り返せます。
4. スペクトラム／ウォーターフォールのクリック、または選局周波数欄で録音帯域内を選局します。元の記録中心と横軸は動かず、復調側をNCOで周波数変換します。復調帯域が記録範囲を超える設定は拒否されます。
5. 既存のFM音声やコンスタレーションを必要に応じてONにします。FMは**放送用モノラル**です。NFMへの対応を追加したものではありません。

対応はRIFF/RF64・2ch PCM8/PCM16/float32（対応サブ形式のextensibleを含む）、250 kS/s～3.2 MS/s。RF64の4 GiB超の位置も64-bitで扱います。PCM16は `/32768` でfloat化し、8-bit化しません。標準解釈はch1=I・ch2=Qです。「I/Q入替」で周波数方向を反転できます。

ファイル入力ではRFゲイン・サンプルレート変更・RTL-SDR接続操作は無効です。「記録中心を補正」はファイルの周波数解釈を補正する操作で、元WAVを書き換えません。最後の入力源とパスは保存しますが、起動時の自動ファイルアクセス・再生は行いません。

ファイルは小ブロックで逐次読み込み、単調時計とサンプル位置で再生を制御します。FM・デジタル処理へのI/Q破棄は行わず、処理遅延は待機で吸収します。50 ms超の遅延では再生時計を再基準化し、バッファ待ちを表示します。FFTは最新ウィンドウを約40 msごとに処理し、表示だけを間引きます。音声出力は最大300 msの待ちバッファに空きができるまで待ち、EOFでは残りを排出します。

| 操作 | 維持／初期化 |
|---|---|
| 一時停止・再開 | 位置、DSP、FFT平均・履歴、未出力音声を維持 |
| ファイル内選局 | 位置と元帯域のFFT・履歴を維持。復調・NCO・音声キューを初期化 |
| シーク・停止・ループ | DSP、FFT平均、表示履歴、音声キューを初期化 |
| FFT点数・窓 | FFT・表示履歴だけ初期化 |
| FM RxBW・デジタル方式/baud等 | 対象DSPだけ初期化 |
| デジタル手動周波数補正 | NCO位相・DSP同期・表示履歴・再生位置・FMを維持 |
| 記録中心・I/Q入替 | 位置を維持し、解釈が変わるDSP・表示・音声を初期化 |

[解析結果と詳細仕様](docs/SDRSharp-IQ-WAV-SPEC.md)。SDR#側で同じ録音を再生したI/Q方向・復調音声の比較は未確認です。PCM24/32整数、float64、モノラル、分割ファイル連結、録音中ファイル、NFMは対象外です。

## 受信・表示

### FM放送の音声受信

1. ドングルに接続して、受信したいFM放送局の周波数を数値入力または画面の左クリックで中心に合わせます。
2. 「FM音声（モノラル）」をONにします。Windowsの既定の再生デバイスから音声が出ます。接続前にONにしておくこともできます。
3. 音量スライダーで0～100%を調整します。初期値は30%、0%はミュートです。Windowsのマスター音量は変更しません。
4. FMをOFF、切断、またはアプリ終了で音声を停止します。FMのON/OFFは音声処理だけを開始・終了し、USB受信・FFT・表示履歴を維持します。

FM放送のモノラル（L+R）音声を扱います。ステレオ分離、RDS、スケルチは未実装です。放送局がない周波数では雑音が聞こえる場合があります。表示帯域は音声の受信帯域とは独立しており、表示を拡大してもFM復調帯域は変わりません。日本のFM放送に合わせてディエンファシスは50 µsです。

既定音声デバイスはFM開始時に開きます。Windows側で出力先を変更した場合はFMをOFF→ONにすると再取得します。音声デバイスのエラー時は画面にエラーを表示し、スペクトラムとウォーターフォールは継続します。

音声処理経路は次のとおりです。

```text
8-bit I/Q → (値−127.5)/128で複素数化
 → 63タップFIRによる2分の1間引きを繰り返し、250～500 kS/s未満へ
 → 129タップFIRで中心±RxBW/2のチャネルを選択（初期値±100 kHz）
 → 隣接複素サンプルの位相差 atan2 によるFM復調（±75 kHz基準）
 → 15 kHz低域フィルター付き64位相FIRで48 kHzへ変換
 → 50 µsディエンファシス → 20 Hz DC除去 → 開始時20 msフェード
 → 上限付き音声バッファ → 音量調整 → 16-bitモノラルPCM
 → WinMM waveOut / WAVE_MAPPER → Windows既定再生デバイス
```

音声フィルターはBlackman窓で設計し、FFT表示用の選択窓やFFT平均値は音声には使いません。復調の状態はUSB受信ブロックをまたいで保持します。FFT点数を変更しても音声側のフィルターや48 kHz出力は変わりません。

USBコールバックは同じ受信配列を表示キューと音声キューへ渡します。表示キューは従来どおり2ブロック、音声キューは最大4ブロックです。音声処理が遅れた場合は古いブロックを破棄し、連番の飛びを検出したら復調器と音声待ちバッファを初期化してフェードインします。

PCM待ちバッファは最大300 ms、再生開始時に120 ms分を蓄積します。出力側は20 ms×3バッファで動作し、通常のソフトウェアバッファ遅延は約0.2秒程度が目安です（USB・Windows・デバイスの遅延は別途）。独立した受信・再生クロックのずれに対して最大±0.1%の補正を行い、不足時は無音、上限超過時は古い音声を破棄して遅延の累積を防ぎます。

音声APIの参照: [waveOutOpen](https://learn.microsoft.com/en-us/windows/win32/api/mmeapi/nf-mmeapi-waveoutopen)、[waveOutWrite](https://learn.microsoft.com/en-us/windows/win32/api/mmeapi/nf-mmeapi-waveoutwrite)、[waveOutReset](https://learn.microsoft.com/en-us/windows/win32/api/mmeapi/nf-mmeapi-waveoutreset)。

### 受信設定

- **FFTポイント数**: 1024 / 2048 / 4096 / 8192 / 16384点から選択。初期値は4096点です。受信中の変更はFFT平均値とウォーターフォール履歴のみを初期化します。USB受信とFM音声は継続します。表示帯域は維持します。点数を増やすと周波数ビンの間隔が狭くなり、1回のFFTに必要な受信時間と処理量は増えます。

- **サンプルレート**: 0.25 / 0.3 / 1 / 1.024 / 1.4 / 1.8 / 2.048 / 2.4 / 2.56 / 2.88 / 3.2 MS/sから選択。初期値は2.048 MS/sです。受信中は選択変更で再設定します。付属ヘッダーに記載されているとおり2.4 MS/sを超える値ではサンプル欠落の可能性があり、候補にも注記しています。
- **RFゲイン**: 初回は自動で接続します。接続時にドングルから対応値を取得すると、自動／手動を選べます。手動にすると右隣のdB値を選択できます。手動の初期候補は対応値のうち20 dBに最も近い値です。設定値はDLLへ渡した後に読み戻して確認します。自動はチューナー自動ゲインであり、ADCのデジタルAGCは従来どおり無効です。
- **表示帯域**: 全帯域、2 MHz、1 MHz、500 / 250 / 100 / 50 kHzのうち受信帯域内の候補を表示します。中心周波数の左右対称に表示し、スペクトラム・ウォーターフォール・カーソル・クリック選局すべてに反映します。サンプルレート低下で現在の表示帯域が範囲外になった場合は全帯域へ戻ります。
- サンプルレート／RFゲイン変更時は現在受信している中心周波数で受信を再開し、過去データを消去します。表示帯域の変更は受信を止めず、既存の履歴も拡大・縮小します。設定できなかった場合は切断状態となり、エラーを画面下部に表示します。
- サンプルレートのDLL読み戻し値を周波数軸とステータス表示に使用します。表示帯域はデジタル上の受信範囲を示すもので、帯域端までアナログ感度が一定であることを保証するものではありません。

- RTL-SDR Blog V1.4.0 の `rtl-sdr.h` と `rtl-sdr_export.h` に基づくCdecl P/Invokeラッパー。
- `rtlsdr_read_async` による実受信。コールバックで8-bit unsigned I/Qをコピーし、上限付きキューを通して別タスクで処理します。処理が遅れた場合は古いブロックを捨て、表示遅延を抑えます。
- 初期値2.048 MS/s、4096点の可変長複素FFT、Hann窓、ブロック平均によるDC除去、FFT shift、線形パワーの指数平均。ビン間隔はサンプルレート÷FFTポイント数（初期設定で500 Hz、16384点なら125 Hz）で、窓による実効分解能の広がりがあります。表示帯域の変更だけではFFT分解能は変わりません。
- 初期表示は中心±1.024 MHz、40 ms周期で画面更新。周波数軸は設定後にDLLから読み戻したサンプルレートと選択した表示帯域を使用します。
- 縦軸は窓の振幅利得で正規化したdBFS/binの相対レベルです。校正済みdBmや電力密度ではありません。自動チューナーゲインにより相対レベルが変わる場合があります。中心のDC近傍はDC除去の影響を受けます。
- 描画幅よりFFTビン数が多い場合は、各画素に対応する最大値を描画して狭いピークを残します。
- 同期読み取りは付属ソースで無期限待ちになるため使用せず、非同期読み取りのキャンセル完了を待ってからcloseします。
- ウォーターフォールはスペクトラムと同じ周波数軸・FFTデータを使い、共通の表示レベル範囲（初期値−120～0 dBFS/bin）を暗色から青・緑・黄・赤に対応させます。右側のカラーバーが色とレベルの対応を示します。最大300行（40 ms更新時で約12秒）を保持します。UI描画周期で新しいフレームを採用するため、厳密な時間目盛りではありません。受信データが更新されない間はスクロールしません。周波数変更・切断時に履歴を消去します。
- FM放送のモノラル復調・音声出力に対応します。AM等の他の復調方式やデジタル信号の解読は含みません。テスト用合成信号は検証プロジェクト内だけにあり、アプリに疑似受信モードはありません。

## 1.7.0の状態復元と描画改善

終了操作時、受信設定の変更完了を待って状態を取得し、受信を停止した後に `%LOCALAPPDATA%\AF-SDR\settings.json` へ保存します。ユーザー別・バージョン共通のJSONで、同じディレクトリに一時ファイルを書き込んでディスクへ反映した後、既存ファイルを置き換えます。通常終了時に保存する方式なので、強制終了・電源断時の直前の変更は保存しません。

保存対象は、ウィンドウの通常位置・サイズ・最大化状態、中心周波数、サンプルレート、自動／手動RFゲインと手動値、表示帯域、FFT点数・窓、レベル上下限、FM RxBW、RxBW表示ON/OFF、音量です。受信中の周波数は適用済みの実周波数を保存し、未接続時は入力が有効なら入力値、不正なら最後の有効値を保存します。

次回は**未接続・FM OFF**で起動します。接続状態・FM ON・デバイスの列挙番号は復元しません。接続や音声の意図しない再開を防ぎ、列挙順変更による別ドングルの選択も避けるためです。FFT平均・ウォーターフォールの受信履歴・音声バッファは新しい受信セッションのデータではないため保存しません。最小化状態も復元せず、最小化する前の通常／最大化状態に戻します。

保存したウィンドウが現在のモニターの作業領域から外れる場合は、最も重なるモニター内へ収めます。重なりがなければ主モニターの中央へ移動します。サイズが大きすぎるときは縮め、負座標に配置したモニターの有効な位置は維持します。保存ファイルが壊れている場合は初期値で起動してステータスに通知し、個別値が範囲外の場合は初期値等へ補正します。

手動RFゲインは、明示的に接続した時点でドングルの対応値を取得して適用します。保存値が非対応なら最も近い対応値、対応値がなければ自動を使用し、実際の値をUIへ反映します。

ウォーターフォールは従来から二重バッファリングされていましたが、リング履歴を折り返し位置で2分割して拡縮描画していました。分割ごとの端数ピクセルの丸めにより、折り返し位置の移動につれて表示行が基準画像とずれることを再現テストで確認しました。履歴画像を上下2領域に複製して、新しい1行だけを両方に更新し、常に連続した1領域を1回で拡縮描画する方式へ変更しました。全履歴を毎フレームコピーしません。更新周期40 ms、300行の履歴、レベル再着色、周波数軸は維持しています。同じFFTフレームの再通知では不要な再描画も行いません。

検証は、全保存項目のJSON往復、既存ファイルの置換、UI復元・終了保存、破損・不正値・非対応形式、モニター消失・負座標・小画面、RFゲイン対応値への調整を含みます。描画は端数倍率でリング一周分を連続した基準画像と比較し、修正前に検出した画素ずれが修正後には発生しないことを確認しています。既存のFM・FFT・UI検証も通過。実機でのちらつきの体感確認は未実施です。

## コンスタレーション表示（1.8.0）

主画面でRTL-SDRに接続し、スペクトラム／ウォーターフォールをクリックするか周波数を入力して、デジタル信号の中心へ合わせます。「コンスタレーション…」で別ウィンドウを開き、方式（BPSK／QPSK）、実際のシンボルレート（baud）、送信信号に合うRRCロールオフαを指定して「表示 ON」にします。解析条件は「適用」で反映し、Symbol Rateと手動周波数補正は桁操作で即時反映します。方式・シンボルレートの自動検出は行いません。

- BPSK／通常のQPSKに加え、1.9.0ではQAM・π/4 Shift QPSK・ASK・FSK・MSKへ対応しました。方式別の表示と設定は次節を参照してください。OFDM、OQPSK、ビット列・通信内容のデコードは対象外です。
- baudは1,000～100,000かつRTL-SDRサンプルレートの1/8以下、αは0.2／0.35／0.5／1.0。初期値QPSK、9600 baud、α=0.35。サンプルレートを下げた場合、baudを使用可能な上限へ補正します。
- デジタル受信帯域の目安は `(1+α)×baud`。FM RxBWや主画面の表示帯域とは独立しています。主画面のRxBWオーバーレイは引き続きFMの帯域です。コンスタレーション画面にデジタルの中心周波数と帯域目安を表示します。
- 「I/Q（同期なし）」はフィルター・振幅正規化後のI/Q散布図です。タイミング／搬送波同期を行わないため、一般の信号をシンボル判定点として表示する機能ではありません。
- 別ウィンドウを閉じるとデジタル処理だけOFFになります。方式・baud・αを前回設定として保存しますが、アプリ起動時はデジタル表示OFF、未接続・FM OFFのままです。

BPSK／QPSKの処理経路は、実受信8-bit I/Q → `(値−127.5)/128` → 63タップ低域FIRによる多段1/2間引き（8～16未満sample/symbol）→ 10シンボル長のRRC FIR → 移動平均パワーによる振幅正規化 → Gardnerタイミング同期（線形補間）→ BPSK／QPSK用Costas搬送波同期 → 最大1024点を保持し最新64～1024点を選択表示、です。I/Qモードは同期段を通らず、1.12.1から内部8 SPSへリサンプリングし、公称1点/シンボルの代表点と中間サンプルの軌跡を表示します。

タイミング周期追従は公称±1%に制限し、搬送波の周波数積分値は±0.15 rad/symbolに制限しています。この値は必ず引き込める範囲の保証ではありません。まず信号中心を正しく合わせ、実際のbaudとαを指定してください。表示の「位相追従補正」はループ内部の補正推定値であり、同期成立の判定や測定器としての確度を示しません。弱い信号、周波数ずれが大きい信号、マルチパス等では点がまとまらない場合があります。自動等化器は未実装です。

USB受信配列をFFT・FM音声・デジタルの各キューで共有し、デジタル処理は専用タスク・最大8ブロックのキューで実行します。欠落時はデジタルフィルター／同期／点群を初期化し、欠落リセット回数を表示します。デジタル設定変更でUSB・FFT・ウォーターフォール・FM音声は初期化しません。逆にFFT窓／点数、FM RxBW／ON/OFFの変更でもデジタル同期を維持します。周波数・サンプルレート・RFゲイン変更時はデジタル処理も初期化します。結果は最大約25回/秒で渡し、主画面の40 msタイマーで描画します。

検証では0.25／1.024／3.2 MS/sの合成BPSK・QPSKに60 Hzの周波数ずれ、100 ppmのシンボルレートずれ、任意の初期位相・タイミングと雑音を与え、2点／4点への収束、入力ブロック分割に対する結果の一致を確認しました。正規化した点群の誤差は約1.2～2.2%。模擬デバイスで設定変更の独立性、設定保存・UI描画、既存機能も検証。実際のデジタル無線信号での確認は未実施です。

同期方式の参照: [GNU Radio Costas Loop](https://wiki.gnuradio.org/index.php/Costas_Loop)、[Symbol Sync](https://wiki.gnuradio.org/index.php/Symbol_Sync)。実装は本プロジェクト内のC#で行い、GNU Radioの実行環境は不要です。

## シングルキャリア変調の表示拡張（1.9.0）

「コンスタレーション…」から開くデジタル信号表示画面で、方式・baudを設定し、必要な多値数・RRC α・FSK隣接トーン間隔を指定して「適用」します。緑は受信値、灰色の＋は参考の基準位置です。受信点を基準位置へ丸めて描くことはありません。目的は信号の視覚的確認で、ビット判定結果やパケットを出力しません。

| 方式 | 表示する内容 | 同期・処理と設定 |
|---|---|---|
| BPSK / QPSK | 従来の2点／4点I/Q | RRC、Gardnerタイミング同期、Costas搬送波同期。baud・αを指定 |
| QAM | 16／64QAMのI/Q点群 | 正方格子QAM。RRC＋Gardner後、2048シンボルの4乗FFTで搬送波周波数を取得、位相探索、判定帰還PLL。多値数・baud・αを指定 |
| π/4 Shift QPSK | 隣接シンボル間の差動位相4点（±45°・±135°） | RRC＋Gardner後に隣接複素積から位相差を取得。4乗の平均で周波数偏差を補正。絶対位相8点の表示ではありません |
| ASK / OOK | 2値／4値の包絡線振幅分布と時間波形 | チャネル低域フィルター→包絡線→RMS正規化→Gardner。搬送波位相同期なし。多値数・baudを指定、RRC αは使いません |
| FSK | 2値／4値の周波数偏移分布と時間波形 | チャネル低域フィルター→隣接サンプル位相差→短い移動平均→Gardner。多値数・baud・隣接トーン間隔を指定 |
| MSK | ±baud/4の周波数偏移分布と時間波形 | 連続位相2FSK（h=0.5）として周波数検出。隣接トーン間隔=baud/2を自動設定。baudは2値シンボル速度。GMSK専用整合処理はありません |
| I/Q（同期なし） | RRC後8 SPSのIQ軌跡と代表点 | 初期表示位相のみ自動選択。継続的なタイミング／搬送波同期なし |

FSKの「隣接トーン間隔」は、2FSKなら2つのトーンの差であり、中心から片側への偏移は間隔の半分です。4FSKでは中心から±間隔/2・±3×間隔/2になります。画面は中心周波数からの実際の偏移をHzで表示し、搬送波ずれを自動的に引いて理想位置へ合わせる処理はしません。必要なら主画面で中心周波数を調整してください。MSKは間隔を編集しません。通常の静止I/Qコンスタレーションとしては扱わず、周波数表示で信号を確認します。

共通の受信経路は、実受信I/Qを既存のFFT・FMとは別タスクへ渡し、アンチエイリアス用63タップFIRで必要な段数だけ1/2間引きを行います。ASKではカットオフ1.5×baud、FSK／MSKでは「最大トーン偏移＋baud」の63タップBlackman窓低域フィルターを使います。後者の位相差検出は `arg(x[n]×conj(x[n−1]))×Fs/(2π)`、平滑化長は作業サンプルレートで約1/4シンボルです。間引きは必要帯域が残る段数で止め、少なくとも8 sample/symbolを保ちます。FSKの間隔が広い場合は作業サンプルレートも高くなります。

多値数の候補は16/64QAM、2/4ASK、2/4FSKです。FSK間隔は100～500,000 Hzかつ受信レートに収まる範囲へ制限します。チャネルカットオフは受信レートの40%以下とし、サンプルレート低下時はbaud・FSK間隔を補正します。時間波形は公称1シンボルあたり8点、最近128点（約16シンボル）、分布は最新64～1024シンボル（初期256）を選択します。ASKの振幅は信号のRMS基準の相対値で、RFゲイン・振幅分布に依存します。基準位置は等確率・等間隔レベルの目安です。

QAMの粗周波数取得は±0.15 rad/symbol内を探索します。PLLで追従するシンボルの判定は位相ループ内部だけに使い、表示する値は補正後の連続した受信値です。π/4方式では一定搬送波位相は差動化で除かれ、周波数偏差は位相差に残る成分を平均して補正します。表示の周波数補正値や「取得完了」は同期成立の保証ではありません。自動方式判定・自動等化・データ復号は行いません。QAMが取得できない場合は、中心周波数・baud・αを確認して表示OFF→ONで再取得できます。

方式・多値数・間隔などの変更ではデジタル処理だけを再初期化し、RTL-SDR接続・FM音声・FFT・ウォーターフォール履歴を維持します。新設定も既存JSONへ保存・復元し、1.8.0の設定ファイルはそのまま読み込めます。起動時の未接続・FM OFF・デジタル表示OFFは維持します。

検証では0.25／2.048 MS/s、60 Hzの搬送波ずれ、100 ppmのクロックずれ、雑音を含む合成信号を使用し、QAM全点・差動位相・ASK振幅・FSK/MSK偏移と、処理ブロックを分割しても結果が変わらないことを確認しました。広い4FSK間隔、低レベル入力、設定保存・入力制限、方式変更が既存処理へ影響しないこと、各方式の描画も検証済みです。実際の無線信号での確認は未実施です。

方式・同期の参照: [MathWorks Carrier Synchronizer](https://www.mathworks.com/help/comm/ref/comm.carriersynchronizer-system-object.html)、[π/4 DQPSK](https://www.mathworks.com/help/comm/ref/comm.dqpskmodulator-system-object.html)、[FSK Modulator](https://www.mathworks.com/help/comm/ref/comm.fskmodulator-system-object.html)。実装はC#で行い、外部DSP実行環境は不要です。
