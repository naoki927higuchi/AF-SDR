# AF-SDR

C# / .NET 9 / WinForms / Windows x64 の最小構成RTL-SDRスペクトラム表示アプリです。

## ビルド・起動

インストール済みの .NET 9 SDK を使用します。外部NuGetパッケージは不要です。

```powershell
cd W:\dev\AF-SDR
dotnet build AF-SDR.sln -c Release
.\AF-SDR\bin\Release\net9.0-windows\AF-SDR.exe
```

1. デバイスを選択します。必要なら「再検索」を押します。
2. 中心周波数を **HzまたはSI接頭語付き** で入力し、「接続」を押します（初期値80,000,000 Hz）。例: `78.4M` → 78,400,000 Hz、`8400k` → 8,400,000 Hz、`100M` → 100,000,000 Hz、`500k` → 500,000 Hz。
3. 受信中は数値を変更して「周波数を適用」またはEnterで変更します。
4. スペクトラム上にマウスを置くと、カーソル周波数をHz/MHzで表示します。左クリックするとその位置を中心周波数に設定します。
5. 下段のウォーターフォールで信号の時間変化を確認できます。最新が上、過去が下です。
6. 「切断」で停止します。ウィンドウを閉じる際も受信終了後にデバイスを解放します。

`k/K`は千倍、`M/m`は百万倍、`G/g`は十億倍です（周波数入力の便宜上、mもMHzとして扱います）。接頭語なしはHzです。`78.4 MHz`、`500 KHZ`、`78,400,000`も入力できます。小数点はピリオド、カンマは3桁区切りとして扱います。設定成功後は整数Hzに整形して表示します。

入力範囲は1～4,294,967,295 Hzで、Hzに換算して整数になる値を受け付けます。不正入力は入力欄のエラーアイコンに表示し、受信・履歴を維持します。実際に受信できる範囲はドングルに依存し、設定エラーは画面下部に表示します。周波数変更時は一度受信を停止して再接続し、古い周波数のデータとFFT平均値を破棄します。

## 受信・表示

### 受信設定

- **FFTポイント数**: 1024 / 2048 / 4096 / 8192 / 16384点から選択。初期値は4096点です。受信中の変更は現在の周波数・サンプルレート・RFゲインで再接続し、FFT平均値とウォーターフォール履歴を初期化します。表示帯域は維持します。点数を増やすと周波数ビンの間隔が狭くなり、1回のFFTに必要な受信時間と処理量は増えます。

- **サンプルレート**: 0.25 / 0.3 / 1 / 1.024 / 1.4 / 1.8 / 2.048 / 2.4 / 2.56 / 2.88 / 3.2 MS/sから選択。初期値は2.048 MS/sです。受信中は選択変更で再設定します。付属ヘッダーに記載されているとおり2.4 MS/sを超える値ではサンプル欠落の可能性があり、候補にも注記しています。
- **RFゲイン**: 初回は自動で接続します。接続時にドングルから対応値を取得すると、自動／手動を選べます。手動にすると右隣のdB値を選択できます。手動の初期候補は対応値のうち20 dBに最も近い値です。設定値はDLLへ渡した後に読み戻して確認します。自動はチューナー自動ゲインであり、ADCのデジタルAGCは従来どおり無効です。
- **表示帯域**: 全帯域、2 MHz、1 MHz、500 / 250 / 100 / 50 kHzのうち受信帯域内の候補を表示します。中心周波数の左右対称に表示し、スペクトラム・ウォーターフォール・カーソル・クリック選局すべてに反映します。サンプルレート低下で現在の表示帯域が範囲外になった場合は全帯域へ戻ります。
- サンプルレート／RFゲイン変更時は現在受信している中心周波数で受信を再開し、過去データを消去します。表示帯域の変更は受信を止めず、既存の履歴も拡大・縮小します。設定できなかった場合は切断状態となり、エラーを画面下部に表示します。
- サンプルレートのDLL読み戻し値を周波数軸とステータス表示に使用します。表示帯域はデジタル上の受信範囲を示すもので、帯域端までアナログ感度が一定であることを保証するものではありません。

- RTL-SDR Blog V1.4.0 の `rtl-sdr.h` と `rtl-sdr_export.h` に基づくCdecl P/Invokeラッパー。
- `rtlsdr_read_async` による実受信。コールバックで8-bit unsigned I/Qをコピーし、上限付きキューを通して別タスクで処理します。処理が遅れた場合は古いブロックを捨て、表示遅延を抑えます。
- 初期値2.048 MS/s、4096点の可変長複素FFT、Hann窓、ブロック平均によるDC除去、FFT shift、線形パワーの指数平均。ビン間隔はサンプルレート÷FFTポイント数（初期設定で500 Hz、16384点なら125 Hz）で、窓による実効分解能の広がりがあります。表示帯域の変更だけではFFT分解能は変わりません。
- 初期表示は中心±1.024 MHz、40 ms周期で画面更新。周波数軸は設定後にDLLから読み戻したサンプルレートと選択した表示帯域を使用します。
- 縦軸は窓の振幅利得で正規化したdBFS/binの相対レベルです。校正済みdBmや電力密度ではありません。自動チューナーゲインにより相対レベルが変わる場合があります。中心のDC近傍はDC除去の影響を受けます。
- 描画幅よりFFTビン数が多い場合は、各画素に対応する最大値を描画して狭いピークを残します。
- 同期読み取りは付属ソースで無期限待ちになるため使用せず、非同期読み取りのキャンセル完了を待ってからcloseします。
- ウォーターフォールはスペクトラムと同じ周波数軸・FFTデータを使い、−110～−10 dBFSを暗色から青・緑・黄・赤に対応させます。最大300行（40 ms更新時で約12秒）を保持します。UI描画周期で新しいフレームを採用するため、厳密な時間目盛りではありません。受信データが更新されない間はスクロールしません。周波数変更・切断時に履歴を消去します。
- 復調、音声出力、デジタル信号の解読は含みません。テスト用合成信号は検証プロジェクト内だけにあり、アプリに疑似受信モードはありません。

## ネイティブDLL

ビルド・publish時に以下の配置済みフォルダーからx64 DLL一式を実行ファイルの横へコピーします。

`W:\dev\Lib\RTL-SDR-BLOG Windows Release V1.4.0\x64`

`rtlsdr.dll`、`pthreadVC2.dll`、`msvcr100.dll` が対象です。ソース参照元は `W:\dev\Lib\rtl-sdr-blog-1.4.0\include` です。プロジェクトを移動する場合はcsprojの相対参照を調整してください。ネイティブライブラリのライセンス・ソースは配置済みLib一式を参照してください。

## ハードウェアを使わない検証

```powershell
dotnet run --project AF-SDR.Checks -c Release
```

正負の周波数、FFT shift、既知トーンの振幅、窓の帯域外抑圧、DC除去、入力変化への追従、DLL読み込み・全使用エクスポート、WinForms描画、ウォーターフォールの履歴折り返し・消去、カーソル周波数変換、クリック選局を検証します。ドングル列挙・接続・ドライバ操作は実行しません。1.0.0の実機スペクトラム表示はユーザー確認済みです。追加機能の実受信確認はアプリで接続して行ってください。

受信設定の候補・範囲、対応ゲイン一覧と0.1 dB単位の変換、表示帯域の制限・切り出し・クリック周波数も検証します。1.2.0までのスペクトラム／ウォーターフォールの実機動作はユーザー確認済みです。

全FFTサイズで正負トーンの周波数と振幅正規化、ウォーターフォールサイズ変更と履歴初期化も検証します。1.3.0までの各機能はユーザーによる実機確認済みです。

1.4.0のビルド済み実行ファイルは `AF-SDR/bin/Release-1.4.0/AF-SDR.exe` にあります。起動中の旧版との出力先競合を避ける場合は `dotnet build AF-SDR.sln -c Release -p:OutputPath=bin/Release-1.4.0/` でビルドできます。
