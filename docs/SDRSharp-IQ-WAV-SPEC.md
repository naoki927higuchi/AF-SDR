# SDR# IQ WAV解析結果とAF-SDRファイル入力仕様

作成: 2026-09-21（JST） / 対象コード: AF-SDR 1.9.0

### チャンク構造

| 位置（byte） | 内容 |
|---|---|
| 0 | `RF64` |
| 4 | 32-bit size = `0xFFFFFFFF`（実サイズではない） |
| 8 | `WAVE` |
| 12 | `ds64`、ペイロード28 bytes、開始20 |
| 20 | 64-bit riffSize = 14,319,688（ファイルサイズ−8） |
| 28 | 64-bit dataSize = 14,319,616 |
| 36 | 64-bit sampleCount = 3,579,904 |
| 44 | tableLength = 0 |
| 48 | `fmt `、ペイロード16 bytes、開始56 |
| 72 | `data`、32-bit size = `0xFFFFFFFF` |
| 80 | PCMデータ開始 |

`80 + dataSize = file size`、`sampleCount × BlockAlign = dataSize`、`sampleRate × BlockAlign = ByteRate`がすべて一致する。末尾の欠損や余剰チャンクはない。通常WAVの44-byte固定ヘッダーとして読む方法や、`0xFFFFFFFF`をデータ長として扱う方法では読み取りを誤る。RF64ではds64の64-bitサイズを使う。[EBU Tech 3306](https://tech.ebu.ch/docs/tech/tech3306v1_1.pdf)

先頭の2チャンネル値は `(495, -1323), (-23, -1063), (1534, 495), …`。チャンネル1の最小/最大は−8063/+8054、チャンネル2は−8331/+7559。16-bit端値でのクリップは0件。両チャンネルの平均は約+0.265/−0.359 count、RMSは約1813 count。16-bit格納であることと、元ADCの有効分解能が16-bitであることは同義ではない。

## 2. 周波数・画面との照合と未確定事項

添付画面にはSDR# v1.0.0.1919、283.487500 MHz、RTL-SDR USB、0.25 MSPS、NFM、帯域20,000 Hzが表示されている。周波数はファイル名、サンプルレートはWAVヘッダーと一致する。

ファイル名の時刻は13:46:26、画像名の時刻は13:47:01で、ファイルの記録時間は約14.32秒。時刻をそのまま解釈すると画像は記録区間より後になるため、瞬時スペクトラムや音声の一致を画像だけから断定しない。日付・タイムゾーンもWAV内部には記録されていない。

チャンネル1をI、チャンネル2をQとして `I+jQ` のFFTを計算すると、中心付近の主なピークは約+5.447 kHzと−3.174 kHzにある（16384点Hann、全完全ブロックの線形パワー平均）。中央に信号があることは確認できるが、この波形だけで変調方式やI/Qの正しい向きを断定しない。画像のNFM選択は受信ソフトの設定であり、信号がNFMだと証明するものではない。

初期のチャンネル解釈は `ch1=I, ch2=Q, z=I+jQ` とする。WAVヘッダーにはI/Qの意味・順序・符号の定義がないため、SDR#で同じファイルを再生した際の周波数方向との照合を受け入れ条件にする。「I/Q入替」をファイル入力設定として用意し、推測による自動反転はしない。入替は周波数方向を反転し、定数位相回転も伴う。

記録中心をファイル名どおりと解釈した場合、記録された理論上の周波数範囲は **283.362500 MHz以上、283.612500 MHz未満**。アナログ感度やフィルターの通過帯域が端まで平坦という意味ではない。

## 3. 初回ファイル入力実装の対応範囲

SDR#の互換性は、まずベースバンドIQ WAVの読み取り互換と定義する。SDR#の全プラグイン、設定ファイル、録音出力、NFM等の全復調方式まで互換と称さない。

- RIFF/WAVEとRF64/WAVEをサポートする。RF64はファイルが4 GiB未満でも必要（今回の実例）。
- 2チャンネルのPCM unsigned 8-bit、PCM signed 16-bit、IEEE float32を対象とする。SDR#配布元の資料でもこの3形式が説明されている。[SDR# Big Book 2024、Baseband Recorder](https://airspy.com/downloads/SDRsharp_Big_Book_2024.pdf)
- `WAVE_FORMAT_EXTENSIBLE`は有効ビット数・サブ形式を検証し、上記と等価なものだけを受け付ける。PCM24/PCM32、float64、圧縮音声、モノラル、3ch以上、複数dataチャンクは初回非対応として理由を表示する。
- サンプルレートはファイル値に固定。初回の再生対応範囲は250 kS/s～3.2 MS/sの連続値とし、RTL-SDR APIの離散候補や禁止区間を適用しない。この範囲外でもヘッダー情報は解析表示し、再生不可の理由を示す。192 kS/sやAirspyの6/10 MS/s等は今後の拡張対象として明記する。
- 中心周波数はファイル名の明示的な`Hz`/`kHz`/`MHz`トークンから取得する（今回の名前、および日時・IQ・分割番号が付く名前を想定）。読めなければ記録中心の数値入力を必須とする。候補が複数ある場合は曖昧な自動選択をしない。
- 初回では未知の周波数メタデータを解釈しない。未知チャンクは安全にスキップし、将来の既知メタデータ対応を追加できる解析結果モデルにする。複数分割ファイルの自動連結は別段階。

### パーサーの条件

チャンク順・ヘッダー長を固定せず、FourCCと長さを順に解釈する。奇数サイズのパディング、未知チャンク、拡張fmtを扱う。RF64のds64と追加サイズテーブル、物理ファイル長、RIFF論理長を64-bit・checked演算で検証する。

今回のようなsentinel付きdataはds64の長さを使う。dataSizeをblockAlignで割り切れない場合、非ゼロsampleCountとの不一致、範囲外チャンク、切断されたデータ、必須チャンク欠落は明示エラーとし、足りないサンプルを無断で補わない。原則として録音終了済みファイルを対象とし、録音中の不完全ヘッダー追跡は実装しない。

## 4. 内部I/Q形式と入力経路

現在のReceiver.Blockはbyte[]、FFT・FM・デジタルDSPはRTL-SDRのunsigned 8-bitを直接変換している。WAVを8-bitへ落としてこの入口へ渡す方式は採用しない。

入力源をRTL-SDRとIQファイルに分け、共通のfloat32複素サンプル（I/Q各float）をDSPへ渡す。メタデータにはサンプルレート、記録中心、元形式、絶対サンプル位置、設定世代・不連続情報を持たせる。実装候補は`IIqSource`相当の入力抽象化と、`IqWaveReader`による独立したファイル解析・読み取り。ファイルを偽のRTL-SDRデバイスとして扱わず、ファイル入力中はrtlsdr.dllのデバイスAPIを呼ばない。

- PCM16: `I = int16(ch1)/32768f`、`Q = int16(ch2)/32768f`。
- PCM8 WAV: 標準のunsigned PCMとして `(byte−128)/128f`。
- float32 WAV: IEEE値をそのまま扱い、8-bit再量子化や勝手なAGCを行わない。NaN/Infinityは位置を示してエラーとする。有限の±1超は入力段で無断クリップしない。
- RTL-SDR入力の既存の `(byte−127.5)/128f` は維持し、ライブ受信の数値結果を不要に変えない。

ファイルは固定サイズのバッファで逐次読み込みし、ファイル全体をメモリに展開しない。4 GiB超の位置・サンプル数も64-bitで管理する。元WAVを上書きしない。

## 5. 再生・選局・音声の操作仕様

入力源ドロップダウンに「RTL-SDR」「IQ WAVファイル」を追加する。ファイル選択で形式・レート・長さ・記録中心とその出典を表示し、読み込んだだけでは再生・音声出力を開始しない。ファイルモードではRFゲイン・デバイス再検索・サンプルレート変更を無効化する。

初回に実装する操作:

- 再生、一時停止、停止（先頭へ戻す）、シーク、位置/全長表示、ループON/OFF（初期OFF）。
- 再生速度は1倍固定。基準は読込バイト数ではなくサンプル位置とヘッダーのFs。
- 単調時計でサンプル時刻を管理する。先読み・キューに上限を設ける。FFT表示は間引き可能だが、音声・デジタル処理のための入力サンプルをUSBのように無断でDropOldestしない。
- ディスク待ち・DSP遅延ではバッファ待ちを表示し、音声不足時は無音。大量サンプルを瞬間投入して追いつこうとせず再生時計を調整する。処理能力不足時には実時間より遅くなり得ることを表示する。
- EOFは正常終了と扱い、「受信が異常終了した」エラーにしない。残りの復調出力を再生して停止し、最終表示を保持する。

### 記録中心と選局周波数の分離

ライブ受信の中心変更はRTL-SDRを再設定するが、ファイルの記録中心は変更できない。この2つを同じ動作に見せない。

ファイルモードでは「記録中心」と「選局周波数」を分離する。スペクトラム・ウォーターフォールの周波数軸は元の記録中心に固定し、選局位置をマーカーで表示する。クリックや数値入力で選局を変えると、復調用I/Qに `exp(−j2π(Ftune−Frecord)n/Fs)` を掛けてデジタル周波数変換する。FFT表示は元のI/Qを使い、記録帯域の見え方を維持する。

選局できるのは記録済み帯域だけ。使用中の復調フィルターの半帯域も含めてナイキスト範囲内か確認し、はみ出す変更は拒否して現在の設定を保持する。FFTの循環やゼロ埋めで未記録帯域が受信できたように見せない。記録中心の手動修正はRFチューニングではなくメタデータ補正として表示し、選局もその記録中心へ戻す。

### NFMとの区別

このWAVは音声ファイルとしてWindowsへ直接出すものではなく、受信入力の代わりにDSPへ供給するファイルである。既存のスペクトラム・ウォーターフォール・デジタル表示・FM放送用モノラル復調へ接続する。

ただし添付画面はNFM / 20 kHz、現行FMは放送用（±75 kHz基準・50 µsディエンファシス）。画像と同じNFM音声処理の再現は、狭帯域フィルター、検波スケーリング、音声帯域、ディエンファシス等を選べるNFMモードの追加として分離する。今回のファイル解析だけから信号の変調方式を決めたり、WFMでNFM再生互換を満たしたとはしない。

## 6. 操作と状態の維持・初期化

| 操作 | 維持 | 初期化・更新 |
|---|---|---|
| 一時停止→再開 | 同じサンプル位置、連続DSP状態、FFT平均・履歴 | 再生時計を再基準化。一時停止時は未出力音声と位置の対応を保つ |
| ファイル内選局 | ファイル再生位置、元帯域FFT・履歴 | 周波数変換器と復調状態・復調待ちデータ。古い選局音声を除去 |
| シーク、停止→先頭、ループ境界 | ユーザー設定 | 入力キュー、DSP履歴、FFT平均、ウォーターフォール、音声バッファを初期化 |
| 表示帯域・レベル変更 | 再生・DSP・履歴 | 表示だけ更新 |
| FFT点数・窓変更 | ファイル位置・音声・デジタル同期 | FFTと表示履歴のみ初期化 |
| デジタル方式・FM RxBW変更 | 再生位置・元帯域表示 | 対象の復調器だけ初期化 |
| 入力源・ファイル変更、記録中心補正、I/Q入替 | UI設定の適用可能な部分 | 古いデータと新しい意味の混在を避けるため受信セッションを再構成 |

シーク・選局で既にWindowsへ送信した旧音声が残らないよう、waveOut側のキューも同期してフラッシュする。単にソフトウェア待ちバッファを消すだけで完全なシークを実現したとはしない。設定保存は最終パス・入力源の選択等に限り、次回起動時の自動ファイルアクセス・再生・音声ONは行わない。

## 7. 実装時の受け入れ条件

1. 今回の原本で80-byteデータ開始、250 kS/s、3,579,904ペア、14.319616秒を一致させる。録音ファイルの内容を変更しない。
2. PCMの先頭サンプル値を独立解析値と照合する。16-bit値を8-bitへ落とさない。
3. 単一複素トーンの合成WAVで周波数の正負、I/Q入替、各PCM/float正規化を確認する。
4. SDR#で同じ原本を再生し、周波数方向・信号位置・レート・全長を照合する。現画像だけを厳密なレベル・向きの正解としない。
5. RIFF/RF64、未知・奇数長チャンク、extensible、ds64テーブル、長大ファイル位置、破損・切断入力を検証する。拡張子だけでは受理しない。
6. 一時停止・シーク・ループ・EOF・ネットワークファイルI/Oエラーを検証し、旧データ・旧音声の混入、長時間の時計ドリフトを確認する。
7. 既存のRTL-SDR・FM・FFT・ウォーターフォール・コンスタレーション・保存復元を回帰検証する。

初回実装は機能追加なので、現在の1.9.0からなら1.10.0が妥当。今回は解析・仕様書だけで、本体の版数とHISTORY.mdは変更しない。
